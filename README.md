# FX Quotes

Сервис на Fiber v3 для асинхронного получения валютных котировок из Frankfurter.

## Локальный запуск

Понадобятся Git и Docker с Docker Compose.

```sh
git clone https://github.com/sanfouse/fx-quotes.git
cd fx-quotes
cp .env.example .env
docker compose up --build -d
```

PostgreSQL и API запустятся автоматически, миграция применится при запуске. API доступен по адресу `http://localhost:3000`.

Настройки задаются в `.env`: таймауты — в формате `5s` или `250ms`, размеры — в байтах. `WORKER_LEASE` должен быть больше `WORKER_ATTEMPT_TIMEOUT`. После изменения настроек повторите `docker compose up --build -d`. При изменении `HTTP_PORT` используйте новый порт в запросах.

`WORKER_COUNT` задаёт количество параллельных воркеров в одном процессе API: по умолчанию `1`, например `WORKER_COUNT=4` запускает четыре обработчика. Значение должно быть положительным. У каждой реплики API свой пул воркеров; при двух репликах с `WORKER_COUNT=4` одновременно работают восемь обработчиков. При остановке процесс дожидается завершения всех своих воркеров.

Воркеры захватывают задачи в PostgreSQL через `FOR UPDATE SKIP LOCKED`, устанавливают `lease_until` и увеличивают `claim_version`. Пока lease действует, задача недоступна другим воркерам. После падения процесса, таймаута попытки или ошибки сохранения незавершённая задача становится доступна повторно по истечении lease. Сохранение результата требует актуальной версии захвата и действующего lease: устаревшая попытка не может перезаписать результат. Ошибка поставщика после завершения его повторных запросов переводит задачу в `failed`, если таймаут попытки ещё не истёк.

При гарантированно единственном обработчике во всём развёртывании можно обойтись без lease и оставлять задачу `pending` до сохранения результата. `WORKER_COUNT=1` ограничивает только один процесс, поэтому lease сохраняется при любом размере пула и позволяет безопасно запускать несколько реплик. Его накладные расходы включают отдельное обновление строки при захвате перед HTTP-запросом; на время обращения к Frankfurter транзакция и соединение с БД не удерживаются. Каждый свободный воркер опрашивает очередь раз в `WORKER_POLL_INTERVAL` (по умолчанию `500ms`); увеличение `WORKER_COUNT` увеличивает число запросов к БД и параллельных обращений к поставщику.

Поддерживаемые валютные пары перечислены в `domain.NormalizePair`, поскольку это правило сервиса: принимаются только шесть пар из EUR, USD и MXN, указанные в OpenAPI. Сервис проверяет это правило до работы с хранилищем, независимо от способа вызова. Проверка ответа Frankfurter остаётся в клиенте поставщика.

`HTTP_READ_TIMEOUT` ограничивает чтение всего запроса, включая заголовки и тело. `HTTP_REQUEST_TIMEOUT` задаёт таймаут операций хэндлера. После перехода на Fiber отдельная настройка `HTTP_READ_HEADER_TIMEOUT` больше не используется.

Отправить запрос на обновление курса:

```sh
curl -i http://localhost:3000/quotes \
  -H 'Content-Type: application/json' \
  -d '{"pair":"EUR/MXN"}'
```

В ответе придёт ID задачи. Подставьте его вместо `1`, чтобы получить результат:

```sh
curl http://localhost:3000/quotes/1
```

Последняя успешно полученная котировка:

```sh
curl -G http://localhost:3000/quotes/latest --data-urlencode 'pair=EUR/MXN'
```

Остановить сервис:

```sh
docker compose down
```

Данные сохраняются в Docker-томе между запусками.

## Тесты

Запуск: `go test -race -count=1 ./...`. Основные сценарии покрыты юнит-тестами с `testing` и Testify. PostgreSQL заменён на `pgxmock`, запросы к Frankfurter — на заглушку HTTP-транспорта. База, миграции и доступ к сети для тестов не нужны.

## Тестовый стенд

Развернул стенд на `https://82.38.71.115`, чтобы можно было попробовать API без локальной установки. Запросы те же — замените `http://localhost:3000` на адрес стенда:

```sh
curl -i https://82.38.71.115/quotes \
  -H 'Content-Type: application/json' \
  -d '{"pair":"EUR/MXN"}'

curl -G https://82.38.71.115/quotes/latest --data-urlencode 'pair=EUR/MXN'
```
